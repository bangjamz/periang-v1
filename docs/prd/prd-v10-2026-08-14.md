## 1. Latar Belakang

`PrediksiRisikoService` di PERIANG saat ini memakai logika **rule-based
placeholder** (skor manual per faktor risiko, maksimal 11 poin) sebagai
pengganti sementara model AI sungguhan. PRD v9 sudah mencatat rencana
mengganti ini dengan model champion ML milik peneliti lewat "InsForge
Model Gateway".

Riset 2026-08-14 menemukan model asli sudah ada dan **siap pakai**:
`champion_model_2022_2024.pkl` — Gradient Boosting hasil Time-Shift
Validation pada data SSGI 2022 & 2024, dipilih sebagai model terbaik dari
5 algoritma yang diuji (Regresi Logistik, Naive Bayes, Decision Tree,
Random Forest, Gradient Boosting) berdasarkan kriteria: (1) Recall ≥ 0.85,
(2) F1-Score tertinggi di antara yang memenuhi (1), (3) konsisten sebagai
kandidat terbaik di kedua arah validasi (2022→2024 dan 2024→2022).

## 2. Tujuan

Mengganti logika rule-based `PrediksiRisikoService` dengan pemanggilan ke
model champion ML asli, supaya prediksi risiko gizi kurang di PERIANG
merepresentasikan hasil riset disertasi secara utuh — bukan lagi
placeholder — sekaligus menjadi bukti penerapan praktis (proof of
practical application) dari model penelitian ke sistem produksi nyata.

## 3. Spesifikasi Model

| Aspek | Nilai |
|---|---|
| Algoritma | Gradient Boosting (scikit-learn `GradientBoostingClassifier`, 150 estimators) |
| Skema validasi | Time-Shift Validation (latih 2022 → uji 2024, arah utama) |
| Recall (sensitivitas) | 0.8639 |
| Precision | 0.2733 |
| F1-Score | 0.4152 |
| AUC-ROC | 0.6799 |
| Threshold klasifikasi | **0.16** (bukan 0.5 — sengaja rendah demi sensitivitas skrining, konsekuensi wajar: precision rendah, banyak false positive by design) |
| Jumlah fitur | 21 (hasil seleksi RFECV) |
| Format file | `.pkl` (joblib-pickled dict: model + threshold + feature_cols + metrics + shap_ranking) |
| Dependency versi | **scikit-learn==1.7.2 persis** (versi lain gagal load — dibuktikan langsung) |

21 fitur (urutan wajib sama persis saat inferensi):
`jenis_kelamin, umur_bulan, jumlah_art, jumlah_balita_rt, pekerjaan_ayah,
pekerjaan_ibu, pendidikan_ayah, pendidikan_ibu, kepemilikan_jamban,
lokasi_air_minum, pembuangan_limbah_cair, pembuangan_tinja,
sumber_air_minum, berat_badan_lahir_g, panjang_badan_lahir_cm,
usia_kandungan_minggu, kepemilikan_buku_kia, imunisasi_hb0,
imunisasi_bcg, imunisasi_dpt_hb_hib_lanjutan, bblr`

Detail arti tiap fitur, kode nilai SSGI, dan mapping ke skema PERIANG:
lihat [docs/champion-model-integration.md](../champion-model-integration.md).

## 4. Keputusan Produk

**Skema Faktor Risiko diperluas ke 21 field granular (fidelitas penuh),
BUKAN mapping perkiraan dengan nilai default** — keputusan user
2026-08-14. Versi lama (5 field: `riwayat_lahir`, `imunisasi`,
`asi_eksklusif`, `sanitasi`, `pendapatan_keluarga`) **dipertahankan, tidak
dihapus** dari skema/kode (kolom lama tetap ada di tabel, nullable/tidak
dipakai lagi oleh form baru) — supaya bisa ditelusuri balik/dibandingkan,
dan data yang sudah terlanjur diisi kader tidak hilang.

## 5. Arsitektur

```
┌─────────────┐     faktor risiko (21 field)     ┌──────────────────┐
│  Next.js     │ ───────────────────────────────► │  Laravel API      │
│  (frontend)  │ ◄─────────────────────────────── │  (backend)        │
└─────────────┘   skor, tingkat_risiko, dst.      └────────┬─────────┘
                                                             │ HTTP POST /predict
                                                             │ (21 fitur JSON)
                                                    ┌────────▼─────────┐
                                                    │  Python           │
                                                    │  microservice     │
                                                    │  (FastAPI)        │
                                                    │  scikit-learn     │
                                                    │  1.7.2 + model.pkl│
                                                    └───────────────────┘
```

Model `.pkl` adalah objek Python — Laravel tidak bisa menjalankannya
langsung. Microservice Python kecil (FastAPI) meng-host model, expose 1
endpoint `POST /predict`. `PrediksiRisikoService::hitung()` memanggilnya
lewat HTTP (`Illuminate\Support\Facades\Http`), lalu memetakan hasil
(`proba`, `risiko_tinggi`) ke kontrak response yang sudah ada. **Kontrak
endpoint `GET /api/balita/{id}/prediksi` tidak berubah** — frontend
(`prediksi/page.tsx`, `prediksi-risiko.ts`) tidak perlu disentuh.

Fallback: kalau microservice tidak terjangkau/timeout, log error dan
kembalikan pesan error yang jelas ke frontend (bukan diam-diam pakai
rule-based lama, supaya user tahu prediksi sedang tidak tersedia — hasil
model ML dan rule-based tidak boleh tercampur tanpa keterangan).

## 7. Kriteria Selesai (Acceptance Criteria)

- [ ] Form Faktor Risiko menampilkan 21 pertanyaan baru + kolom lama tetap
      ada di database (tidak dihapus).
- [ ] Microservice `/predict` mengembalikan probabilitas yang identik
      dengan hasil `model.predict_proba()` langsung di Python (sudah ada
      baseline test manual 2026-08-14: sample berat lahir 3200g dsb →
      proba 0.1117).
- [ ] `GET /api/balita/{id}/prediksi` mengembalikan skor/tingkat_risiko
      berbasis output model ML asli, bukan lagi rule-based.
- [ ] Kontrak response tidak berubah — halaman `/prediksi` di frontend
      tetap berfungsi tanpa modifikasi.
- [ ] Kalau microservice mati, endpoint mengembalikan error yang jelas
      (bukan crash 500 tanpa pesan, bukan juga diam-diam fallback tanpa
      keterangan).

## 8. Risiko & Catatan

- **Precision rendah (0.27)** adalah karakteristik model yang disengaja
  (threshold rendah demi recall tinggi) — bukan bug. Perlu dikomunikasikan
  ke kader/pengguna lewat teks di UI supaya paham hasil "risiko tinggi"
  bermakna "perlu diperiksa lebih lanjut", bukan "pasti gizi kurang".
- **Metrik model (Recall 0.86, AUC 0.68) berasal dari populasi SSGI**
  (survei nasional) — performa di populasi lokal posyandu pengguna PERIANG
  bisa berbeda; ini bukan bug implementasi, melainkan batas generalisasi
  yang wajar didiskusikan di Bab IV/V disertasi.
- Versi scikit-learn harus dikunci persis di `requirements.txt`
  microservice — kalau VPS/CI menginstal versi lain, model gagal load
  total (sudah dibuktikan langsung saat riset).
